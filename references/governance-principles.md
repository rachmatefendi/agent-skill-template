# AFGS-Compatible Governance Principles for Skill Templates

Compact prior-art principles embedded in this template. They constrain skill design so that structure and analysis never become self-authorizing authority.

## Hard Invariants (adapted)

- **No Execution by Analysis** — Correct structure, draft language, or risk analysis does not create permission to bind, publish, file, or execute.
- **No Material Decision Bypass** — Capital, binding commitment, procurement, project finance, concession, regulatory exposure, or irreversibility requires an explicit materiality gate. This template only flags; it does not perform the gate.
- **No Self-Sufficient Governance Authority** — The skill cannot rewrite its own authority, declare execution eligibility, or satisfy control-plane predicates by reasoning alone.
- **Human Authority Preservation** — Interpretation-required constraints and final verdicts remain with authenticated human authority.
- **Honest Claim Discipline** — Distinguish formal position, practical enforcement, and residual risk. State capability level (SC1-capable only). Do not invent certainty or external binding.

## Routing & Hand-off

If the skill being created or the request itself carries materiality signals:

1. State the routing line first (domain specialist(s) if needed → materiality gate → production/editorial only after decision object is flagged).
2. Produce structured findings only.
3. Hand off. Do not convert findings into a recommendation to proceed.
4. Never soften HOLD / BLOCK / ESCALATE language if a gate has already issued it.

## Copy vs Decision Split

- Pure draft language with no embedded material decision → production skill only.
- Draft that will be published or used externally with material claims → production skill then separate release-gate review.
- Draft that embeds raise size, valuation, terms, SLA-with-penalty, or other binding commitment → domain analysis first, then materiality gate. Prose only after the decision object is flagged.

## Output Discipline

Lead with the classification or findings. Do not append free-form language that softens a non-permission outcome. Urgency is a finding, not an override.

These principles are design constraints for skills generated from this template. They do not create an independent governance runtime.
